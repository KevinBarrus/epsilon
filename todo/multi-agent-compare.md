# 指令：多 Agent 对照跑（同任务 / 同 goal / 同指标）

## 目的

单 Agent 已有干净基线：**33,317,726 token / 47 分 25 秒 / 16 次工具错误 / 75/75 + tsc 通过**。现在用**完全相同的任务和配置**跑多 Agent（唯一变量：委派），对比同样三个主指标。

## 配置（只改"委派"这一个变量）

- **任务**：复制 epsilon 到副本，把副本 `src/core` 从 Python 重构成等价 TypeScript；harness 从原代码跑；
- **模型**：`deepseek-flash`，`thinking=high`；
- **goal**：objective 与单 Agent 完全一致，预算同样**只有安全熔断**（`token_budget=50_000_000`、`time_budget_seconds=7200`），跑到 `goal complete` 或熔断；
- **委派**：**开** —— 注册 `spawn_agent`（Scout）/`spawn_worker`(Worker) / `spawn_reviewer`(Reviewer) 并注入子 Agent 使用说明。

## 关键：本轮必须真正用上多 Agent

之前的实测表明，**模型在编码/重构任务上不会自然委派**（委派率 0）。若本轮仍放任，就跑成第二轮单 Agent，拿不到多 Agent 数据点。因此：

- prompt 中**明确要求委派**：把 `src/core` 按独立模块分组，**用 Worker 完成迁移**，用 Reviewer 做验证；
- 记录实际委派次数——如果模型仍拒绝委派，如实记录"指令要求下仍未委派"，这本身也是结论。

## 记录指标（与单 Agent 一一对应）

1. **准确的**总 token、总耗时；
2. **失败次数**：工具错误数、重试数、各采样点 `tsc` 失败；
3. **委派统计**：`spawn_agent`/`spawn_worker`/`spawn_reviewer` 各几次、委派顺序；
4. **各角色 token 分解**：父 Agent + 每个 Worker/Reviewer 各自用量（这是在总 token 之上的额外视角）；
5. goal 最终状态、续跑次数；
6. 进度曲线（每 25 轮/2 分钟：TS 文件数、模块映射、tsc 状态、累计失败）；
7. 完成声明真实性（独立核实 75/75 + tsc）。

## 诚实提醒（先说清预期，避免误读）

- **Worker 是串行的**（共享工作区、避免写冲突），所以**墙钟时间不一定减少**——多 Agent 这里拿不到"并行加速"，除非做 worktree 隔离；
- **子 Agent 要重新读项目**（无父上下文），**token 大概率增加**；
- 因此可能出现"多 Agent 用更多 token、且不更快"——**若如此，如实记录**，那就是"在文本通信 + 共享工作区的约束下，多 Agent 对这类重构任务不划算"的结论；
- 本轮是**单次运行**，方差未知，只作工程观察。

## 约束

- 跑前报费用确认（多 Agent token 可能到 40M+ 量级）；
- 副本机制，原仓库零改动；
- 诚实记录，委派率、虚报、失败都如实标注；
- 只改评测脚本（接入委派 + 鼓励委派 prompt），不改生产逻辑。
