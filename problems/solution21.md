# 第二十一轮优化方案：SWE-bench 运行环境契约

## 目标与边界

- 让模型在真实评测中基于事实使用工作区和工具，而非猜测 Docker 路径
- 保持生产 Agent 的通用提示词不包含 SWE-bench 专用假设
- 不为特定仓库硬编码测试命令，仍由模型从仓库配置和现有测试中判断
- 不增加新的评测框架、配置层或依赖

## 问题一方案：仅在评测任务提示词追加动态环境契约

1. 将评测工作区路径传入 `_agent_prompt()`
2. 在 Issue 前说明：`run_command` 已在该工作区根目录执行，不应猜测或 `cd` 到 `/workspace`
3. 说明文件工具使用相对工作区路径，`search_files.path` 必须是目录，搜索根目录使用 `"."`
4. 说明工作区是无 Git 历史的源码快照，不依赖 Git 命令调查
5. 要求测试前先检查仓库已有的测试配置和相邻测试；配置或导入失败时先诊断测试入口，再修改生产代码

## 问题二方案：让搜索范围错误可恢复

将 `search_files` 的错误改为：路径必须是存在的目录，并提示仓库根目录使用 `"."`。不暴露绝对工作区路径，避免影响生产环境的路径边界。

## 问题三方案：记录固定环境契约版本

在评测事件中写入固定版本号 `swebench_environment_contract`。后续同一任务复跑时，可区分是否使用了本轮环境引导。

## 测试计划

- `_agent_prompt()` 包含传入的工作区、命令工作目录、搜索目录约束和测试诊断约束
- 搜索范围是文件或不存在路径时，返回可行动的目录提示
- SWE-bench 运行事件包含环境契约版本

## 验收标准

- 评测提示词明确表达运行环境事实，不再要求模型猜测 `/workspace`
- 搜索错误能引导模型改用目录或 `"."`
- 结果轨迹可辨别是否使用本轮环境契约
