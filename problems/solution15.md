# 第十五轮优化方案：终端鼠标交互与输入光标

## 总体原则

- 鼠标协议、事件解析和终端输出模式集中在 `screen.py`
- `ConversationView` 继续只负责滚动位置和自动跟随
- `SelectionPane` 继续只负责鼠标事件到滚动、拖选复制的分流
- 不修改对话布局、状态栏、输入框方向键和业务层逻辑
- 使用终端原生光标闪烁，不增加渲染定时器

## 问题一、二方案：使用完整鼠标协议处理滚动和缩放

### 实施步骤

1. 删除旧式 Ctrl+滚轮事件码的临时映射及对应测试
2. 自定义输出层成对启用、关闭完整鼠标协议：基础点击、拖动、任意移动、焦点事件和 SGR 鼠标事件
3. 保留 `mouse_support=True`，让 prompt-toolkit 原生解析 SGR 鼠标事件及其修饰键
4. 普通滚轮仍由 `SelectionPane` 调用 `ConversationView.scroll_by()`；带 Control 修饰的滚轮继续不进入应用滚动逻辑
5. 使启用和关闭序列严格成对，避免程序退出后残留鼠标模式影响外层终端

### 分层关系

```text
终端鼠标事件
    ↓
prompt-toolkit 解析 SGR 事件
    ↓
SelectionPane
    ├── 普通滚轮 → ConversationView.scroll_by()
    ├── Ctrl+滚轮 → 不消费对话滚动
    └── 左键拖动 → 选区复制
```

### 测试与验收

- 单元测试覆盖完整鼠标协议的启用和关闭序列
- 单元测试覆盖普通滚轮滚动、Ctrl+滚轮不滚动对话
- 真实终端中发送长回复后，滚轮和触摸板可向上、向下查看历史
- 用户停留在历史位置时，新输出不强制跳回底部
- Ctrl+滚轮不再产生异常，并在支持该能力的终端中完成缩放
- 退出应用后，外层终端鼠标行为正常

## 问题三方案：保留闪烁光标状态

### 实施步骤

1. 保留 `BLINKING_BEAM` 作为输入光标形状
2. 覆写输出对象显示光标的方法，只发送“显示光标”序列，不发送关闭闪烁的序列
3. 不改变隐藏光标、退出恢复光标形状和常规渲染流程
4. 增加输出序列测试，确保后续重绘显示光标时不会关闭闪烁

### 测试与验收

- 单元测试验证输入光标形状仍为闪烁竖线
- 单元测试验证显示光标的输出不包含关闭闪烁序列
- 真实终端中静止等待、流式输出和 spinner 刷新后，光标持续闪烁
- 不支持闪烁的终端中，输入框仍可见、可编辑且不报错
