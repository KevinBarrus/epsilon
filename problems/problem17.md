# 问题 17：行内历史渲染与流式 Markdown 展示不一致

## 问题一：历史用户消息丢失灰色背景

当前行内视口会把已完成的用户消息转换为纯文本，再写入终端主屏幕回滚区。用户消息原有的灰色背景仅存在于活动界面的窗口样式中，因此历史消息进入回滚区后无法与模型输出清晰区分。

期望行为：

- 当前消息和向上滚动查看的历史消息都能清楚区分用户与模型
- 用户消息保留类似灰色背景框的视觉层次

## 问题二：流式 Markdown 在代码块和表格处卡顿，稳定历史丢失样式

流式回复每收到一个分片，都会重新解析整段 Markdown；代码块还会重复对全部已输出代码进行语法高亮。回复变长后，重复解析会阻塞界面刷新，表现为普通文本尚可流式显示，进入表格或代码时停顿，之后才出现最终结果。

此外，已完成的模型消息会转换为纯文本写入终端历史，导致最终展示没有 Markdown 格式和代码关键字颜色。

期望行为：

- 代码块和表格到达时仍保持连续的流式体验
- 代码、表格和普通 Markdown 在稳定历史中保持可读的格式与颜色
- 不因回复长度增加而明显拖慢界面

## 问题三：代码块前出现重复空行

Markdown 渲染器在代码块内部收集代码行时，仍按普通行追加换行；代码块结束后又重新渲染收集到的全部代码，造成换行被重复写入。模型输出代码时，代码语言和第一行代码前会出现大量不属于原始回复的空白。

期望行为：

- 代码块前后只保留 Markdown 原文应有的换行
- 不改变代码本身的缩进与内容

## 问题四：终端缩放后输入框上边框重复叠加

当前使用非全屏行内视口。终端缩放触发尺寸变化后，活动界面会重新绘制；旧帧的输入框上边框没有被可靠覆盖，于是每次放大都会在输入框上方多出一条横线。该问题不是边框组件被重复创建，改成灰色输入框也不能从根本上解决。

期望行为：

- Ctrl+滚轮和触摸板缩放后界面不残留旧帧
- 输入框始终只有一条上边框和一条下边框
- 保持行内历史、终端原生滚动和缩放能力
