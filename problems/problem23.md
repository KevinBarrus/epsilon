# 问题 23：SWE-bench 的 Agent 执行环境与官方裁判环境不一致

## 一、问题背景

Epsilon 的真实 SWE-bench 评测分为两个阶段：

```text
Agent 阶段
  宿主 Python 与宿主依赖中执行 run_command
  ↓
生成补丁
  ↓
官方 Harness 阶段
  在任务官方实例镜像中应用补丁并运行隐藏评测
```

两个阶段使用的 Python 版本、依赖集合、环境变量和工作目录并不相同。Agent 根据宿主命令输出决定下一步，而最终通过与否由官方实例容器决定，因此形成了“执行反馈”和“最终裁判”脱节的问题。

## 二、发现过程与排查证据

### 1. retry6 的异常结果

对五个 Django Lite 实例执行 retry6 后，结果为 `0/5 passed`：

| 实例 | 写后本地命令 | 官方 Harness | 停止原因 |
| --- | --- | --- | --- |
| django__django-11019 | passed | failed | tool_limit |
| django__django-11283 | failed | failed | completed |
| django__django-11905 | failed | failed | tool_limit |
| django__django-13321 | failed | failed | completed |
| django__django-14155 | 无 | 无 | 模型请求超时 |

`14155` 在进入 Agent Loop 前发生模型请求超时，属于网络或模型服务故障，不应归因于工具或补丁能力。

### 2. 宿主运行环境不兼容的直接证据

`11283` 的 Session 工具输出中，旧版 Django 在宿主 Python 3.12 运行测试时出现：

```text
AttributeError: 'RemoteTestResult' object has no attribute 'addDuration'
RuntimeWarning: TestResult has no addDuration method
```

这说明模型收到的失败并不完全来自它写入的补丁，也可能来自宿主解释器与旧项目测试运行器的不兼容。

### 3. 本地“passed”不是补丁正确性的证明

当前 `local_verification_status=passed` 的定义是：最后一次文件写入后，至少一条 `run_command` 以退出码 0 结束。它并不识别命令是否真为测试，也不代表完整目标测试通过。

因此，`11019` 的“本地 passed、官方 failed”说明本地反馈不足以作为最终依据，但不能仅凭这一项断言全部差异由 Python 版本造成。官方日志还显示该补丁有多个目标测试失败，模型的代码理解与测试选择同样存在问题。

### 4. 另外两个独立问题

- `11283`、`13321` 在写后命令失败后仍自然结束。当前策略只要求“发生过命令尝试”，不会在失败后要求模型处理失败输出
- `11905` 的官方日志显示补丁未成功应用。这是补丁生成或应用兼容性问题，切换命令执行容器无法直接修复

## 三、根因

根因不是单一的“模型能力差”或“工具轮次不足”，而是四类问题叠加：

1. Agent 命令运行在宿主环境，官方裁判运行在任务实例镜像，验证环境不一致
2. 当前本地验证状态只描述命令退出结果，不描述测试覆盖或补丁正确性
3. 写后验证策略对失败命令缺少一次受限的收尾引导
4. 补丁生成、模型推理和网络请求仍可能独立失败

## 四、影响

- 模型可能基于宿主兼容性错误做无效修复
- 模型可能因一个无关成功命令而误以为已完成
- 评测报告若不区分两类结果，容易把环境问题错误归为模型或补丁问题
- 即使提高工具轮次或并行度，也无法消除错误环境反馈

## 五、面试表达

这个问题体现的是 Agent Harness 的关键职责：Harness 不只负责“把命令跑起来”，还要保证模型用于决策的反馈与最终裁判尽可能同源。

可以这样表述：

> 在 SWE-bench 回归中，我发现模型在宿主 Python 上得到的测试结果与官方容器裁判不一致。排查后确认旧 Django 测试运行器与宿主 Python 3.12 不兼容，同时现有状态只能说明命令退出成功，不能证明补丁正确。因此我没有把官方通过率直接归因于模型，而是将命令执行环境抽象为可替换后端，并计划在评测模式下把 `run_command` 路由到官方实例镜像；官方 Harness 仍独立复核补丁，避免 Agent 自测成为自证。

## 六、边界

- 本问题只处理 SWE-bench 评测环境一致性，不改变普通用户运行 Epsilon 时的宿主执行行为
- 不向模型暴露参考补丁、隐藏测试补丁或官方评测脚本
- 容器内命令结果仍不是最终裁判，最终通过率只以独立官方 Harness 为准
