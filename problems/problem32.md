# 工单：工具调用追踪与大仓库搜索修复

## 一、背景

上一次 Scout 冒烟评测中，父 Agent 或 Scout 生成了 `search_files` 调用，并将搜索范围扩大到工作区根目录。当前工作区包含大量评测历史，Python 实现会逐个目录、逐个文件执行 `stat`、打开和读取，导致一次工具调用长时间占用事件循环。由于现有事件只在工具完成后记录，最终无法确认是谁发起了搜索、搜索了哪个路径，也无法在中断前留下结果。

本工单只处理两个问题：

1. 工具调用必须记录发起方、参数、开始/结束时间和取消状态；
2. `search_files` 改用可取消的 `rg` 子进程，并默认遵守项目 `.gitignore`。

## 二、目标

- 能回答“父 Agent 还是 Scout 发起了工具调用”。
- 能看到工具名、调用参数、开始时间、耗时和最终状态。
- 工具被取消时能记录 `cancelled`，并回收搜索子进程。
- 普通代码搜索不再由 Python 在事件循环中同步遍历整个工作区。
- 保留现有 `search_files` 的工具接口和输出格式兼容性。
- 不增加固定的用户可见文件数硬上限，不把特定目录名写死为唯一解决方案。

## 三、实现方案

### 3.1 工具调用生命周期记录

给 `AgentLoop` 增加调用方标识：父循环使用 `parent`，Scout 循环使用 `scout`。新增工具开始事件；完成事件补充调用方和耗时；取消时记录取消事件。评测脚本将这些事件落盘，至少保存：

- `agent_role`
- `tool_name`
- `call_id`
- 工具参数中的 `path`、`pattern` 等诊断字段
- `started_at`、`finished_at`、`duration_ms`
- `status`: `completed`、`error` 或 `cancelled`

现有完成事件和批次事件继续保留，避免破坏 UI 和已有统计。

### 3.2 使用 `rg` 实现搜索

`search_files` 使用 `asyncio.create_subprocess_exec` 调用 `rg`，不拼接 shell 命令。参数包括行号、文件名和纯文本输出。工具逐行读取标准输出，达到现有工具输出限制后返回带有“结果已截断、请缩小路径”的提示。

默认不使用 `--no-ignore`，让 `rg` 遵守 `.gitignore`，因此评测结果、虚拟环境和缓存等被忽略目录不会被无意扫描。用户显式指定某个路径时仍可以搜索该路径。

搜索进程被取消时，终止并回收 `rg` 子进程。`rg` 返回“无匹配”时仍返回原有的 `no matching content found`；其他非零退出码转换为工具错误。

### 3.3 搜索路径提示

不强制把 `path` 改成必填。更新工具说明，提示模型优先指定 `src/`、`tests/` 等与任务相关的目录，只有确实需要时才使用工作区根目录。路径选择仍由模型决定，不依赖硬编码排除目录才能工作。

## 四、边界与不做事项

- 不修改 Scout 并发、超时、轮次上限和独立上下文机制。
- 不新增固定的文件数/字节数扫描上限；现阶段只限制返回给模型的结果量。
- 不用线程伪装成异步扫描；搜索由可终止的子进程负责。
- 硬超时只作为最后保险，不作为搜索正确性的主要方案。
- 不修改工具权限语义，不绕过审批。

## 五、测试与验收

先补测试再改实现：

1. 工具开始、完成、取消事件携带 `agent_role` 和调用信息。
2. 父 Agent 与 Scout 使用不同角色标识。
3. `search_files` 调用 `rg` 时传递 pattern/path，并遵守 `.gitignore`。
4. `rg` 输出逐行收集，结果达到输出限制时返回截断提示。
5. 搜索任务取消时，子进程被终止且工具不会遗留后台进程。
6. 无匹配和 `rg` 错误分别保持预期返回。
7. 既有文件工具、AgentLoop、Scout 和全量测试保持通过。

完成后做一次本地诊断运行，确认结果中能直接看到：发起方、搜索路径、耗时和是否取消；不立即重跑高成本真机冒烟。
