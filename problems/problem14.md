# 问题 14：TUI 交互与运行状态展示仍存在明显缺陷

## 发现来源

本轮对当前项目进行实际 TUI 体验检查，并结合用户对 Pi、Codex 和 Claude Code 交互方式的观察。问题集中在命令补全、启动页、对话滚动、输入框、终端缩放，以及模型和工具执行过程的可见性。

本轮与 `problem13.md` 中的 Logo、缩放、working、工具折叠和输入框问题有部分重叠。`problem13.md` 是此前的实现计划；本文件记录本次重新核对后仍需要明确修复或验收的具体表现，后续执行以本文件和 `solution14.md` 为准，避免同一问题被重复设计。

## 问题一：slash command 补全列表不能随选中项滚动

输入 `/` 后会展示 slash command 列表，但连续按 ↓ 超过当前可见区域后，列表窗口不再滚动，选中项可能已经位于窗口之外。

期望行为：选中项始终位于可见列表范围内；向下选择时窗口向下滚动，向上选择时窗口向上滚动；到达首尾时做循环跳动。

## 问题二：Logo 使用 Unicode 方块字导致显示异常，且缺少明确的 ASCII 方案

当前 Logo 使用 Unicode 方块字符拼成图案，在部分终端、字体或宽度计算环境中会显示为乱码、方块堆叠或不完整图形，无法稳定展示 `ε EPSILON` 的品牌信息。

本轮确定改用普通 ASCII 字符设计 Logo，不再依赖 Unicode 方块字、图片字体或终端特殊字形。ASCII Logo 需要在常见终端字体下保持可读，并能被现有纯文本渲染链路稳定展示。

## 问题三：Logo 与前置信息未形成大气、居中的启动页布局

Logo 下方的欢迎信息、模型信息或使用提示当前存在左对齐、行间距过小的问题。Logo 和前置信息应作为一个整体居中展示，并通过适当的空行增强层次。

本问题只调整启动页内容的布局，不改变底部状态栏。状态栏已有的工作目录、上下文信息、余额、当前使用金额、模型信息和复制信息必须继续保留在原位置和原有职责中。

## 问题四：Ctrl+滚轮或触摸板缩放未稳定生效

当前项目尝试通过应用层输出终端控制序列调整字体大小，但在 WSL/Windows Terminal 环境下未稳定生效。问题可能与 prompt-toolkit 启用鼠标协议后拦截 Ctrl+滚轮有关，也可能受终端自身能力限制。

期望行为：普通滚轮继续用于 TUI 滚动，Ctrl+滚轮尽可能交还终端处理以实现原生缩放；应用不应把终端不支持的字体缩放伪装成已成功。无法由应用控制的终端差异需要在文档和手动验收中明确。

## 问题五：无法可靠使用鼠标上下滚动查看历史对话

当前对话区存在严重的历史查看问题，用户无法稳定地使用键盘查看过去消息。需要明确区分：

- 对话历史滚动由鼠标滚轮、PageUp/PageDown 等完成
- 输入框中的 ↑/↓ 由输入编辑器处理
- 当输入框因对话滚动而不可见时，输入框编辑操作应使界面回到底部

不能简单地把 ↑/↓ 全局绑定为对话滚动，否则会破坏多行输入和历史输入恢复。

## 问题六：输入光标不闪烁

代码中虽然设置了闪烁光标形状，但实际终端中光标始终静止。该问题可能不是 Python 渲染逻辑错误，而是终端对光标控制序列、光标形状或闪烁设置的支持差异。

需要区分应用能够保证的部分与终端决定的部分：应用应正确请求闪烁光标，但不应为了强行模拟闪烁而引入高频重绘和额外定时器，造成 TUI 性能或输入体验退化。

## 问题七：模型思考、工具执行和等待状态展示位置与模式不一致

当前 working/thinking 信息主要位于状态栏，不能充分反映对话区内正在发生的工作。用户希望根据 `/thinking-toggle` 的状态采用两种模式：

- 开启思考展示时，直接展示模型推理内容，不额外显示冗余的 working 计时
- 关闭思考展示时，在对话区显示 `working for ...s`，模型开始调用工具后显示工具名称和执行耗时，完成后显示最终耗时信息

工具执行期间应有明确的活动状态和转圈效果，避免模型没有文本输出时用户误以为程序卡死。已有状态栏的静态信息不能被这些动态消息替换。

## 问题八：工具调用和工具结果缺少一致的省略与状态展示

对于命令、写文件等大参数或大结果，完整展示会占据大量对话空间；完全截断又会让用户无法判断工具是否真实执行、结果是什么。

期望行为：

- 工具开始执行时，在对话区显示精简的工具名称、关键参数摘要和 working 状态
- 大参数和大结果默认折叠，显示省略行数以及展开提示
- 工具完成后显示成功、失败或取消状态，并保留适量结果摘要
- 用户可以使用明确的快捷键展开或收起最近的工具结果
- 省略只影响 TUI 展示，不应修改传给模型的原始工具结果，也不应破坏 JSONL 持久化

## 问题九：输入框超出显示高度时缺少或未稳定显示隐藏行提示

输入内容超过输入框最大高度后，上方不可见的行数需要明确显示为 `↑ n more`。该提示应随输入框内容变化正确更新，不应遮挡光标、底部输入区域或状态栏。

同时需要与 Codex 式方向键行为配合：输入框为空时 ↑/↓优先恢复历史输入；输入框有内容时 ↑/↓只移动多行文本光标；当输入框因对话滚动不可见时，编辑操作让界面回到底部。
