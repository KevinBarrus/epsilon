# 第二十二轮优化方案：项目上下文与写后验证闭环

## 目标与边界

- 让生产 Agent 自动获得可信项目指令，不把 SWE-bench 专用内容写入通用提示词
- 在实际发生文件写入后要求一次可追溯的验证，而不让模型“自称已验证”直接结束
- 不将任意成功命令误判为测试成功，不引入脆弱的命令字符串识别
- 不实现任务规划器、无限修复循环、项目类型识别器或针对 Django 的硬编码命令

## 统一流程

```text
启动工作区
  ↓
发现可信项目指令并加入系统上下文
  ↓
模型读取源码、修改文件、调用工具
  ↓
模型自然结束
  ├── 本轮无文件写入 → 正常结束
  ├── 写入后已有验证尝试 → 正常结束并保留验证结果
  └── 写入后无验证尝试 → 仅注入一次验证提醒，再请求模型
                                      ↓
                           第二次自然结束后放行
```

## 问题一方案：加载工作区 `AGENTS.md`

1. 新增独立的项目指令加载模块，只负责从工作区根目录向上发现 `AGENTS.md`，按由外到内的顺序读取
2. 只读取工作区及其父级边界内的文件；每个文件和总内容使用固定字节上限，超出时明确截断标记
3. 以“项目提供的工作说明”区块追加到系统提示词，不覆盖内置安全规则、工具权限或用户指令
4. 启动时加载一次；恢复会话或工作区未变化时复用，不在每次模型请求重新扫描磁盘
5. 读取失败、编码异常或不存在时静默降级为空项目说明，并保留可测试的加载结果

### 安全边界

- `AGENTS.md` 是项目上下文，不是高于系统和用户指令的权限来源
- 文件内容不能改变工具审批、工作区路径校验或错误处理策略
- 不扫描隐藏目录、子目录中的任意说明文件，也不自动执行说明中提到的命令

## 问题二方案：加入可选的写后验证结束策略

1. 为 `AgentLoop` 增加可选回合结束策略协议；默认不启用，保持纯问答和现有交互的结束行为
2. 策略仅追踪本轮明确的 `write_file`、`edit_file` 工具调用，以及它们之后的 `run_command` 调用结果
3. 若模型自然结束、发生过写入、写入后没有任何命令验证尝试，向上下文追加一条固定验证提醒并继续一次
4. 提醒要求模型运行相关验证，或清楚说明无法验证的原因；不声称任意成功命令等于测试成功
5. 验证提醒最多注入一次；第二次自然结束、用户取消、工具上限、模型异常均直接结束，避免验证死循环
6. `AgentRunResult` 与评测事件记录是否注入过验证提醒、写入次数和写后命令结果，供后续评测归因

### 边界

- 第一版的“验证证据”是写入后发生的命令验证尝试，不判定命令是否真是测试
- 不对 `run_command` 的任意副作用做猜测；命令可写文件时仍保持既有审批与串行语义
- 不把工具结果文本交给规则引擎解释，是否修复仍由模型根据完整输出决定

## 问题三方案：SWE-bench 启动时提供仓库资料索引

1. 仅在 `evaluation/swebench.py` 中，从工作区根目录检查固定候选文件：`README*`、`CONTRIBUTING*`、`pyproject.toml`、`setup.cfg`、`tox.ini`、`tests/README*`
2. 只将存在文件的相对路径列表写入评测环境契约，要求模型优先读取这些资料以确定测试方式
3. 不直接将完整文档塞入上下文，不指定 Django 或其它仓库的测试命令

## 问题四方案：将容器内验证列为独立评测能力

1. 保持当前官方 Harness 最终验证不变，继续作为补丁正确性的唯一裁判
2. 在评测结果中区分“Agent 本地验证命令失败”和“官方 Harness 未通过”，避免把宿主解释器兼容性错误归因为补丁错误
3. 后续单独设计容器内 Agent 工具执行：Agent 工作区、Python 和依赖必须与任务官方镜像一致，并处理容器生命周期、文件同步、命令超时和安全边界
4. 在容器内工具执行完成前，不把宿主 Python 测试结果作为 solve-rate 评测的关键依据

## 执行顺序

1. 实现并测试项目指令加载，接入生产系统提示词
2. 实现并测试可选写后验证策略，先在 SWE-bench 启用
3. 实现 SWE-bench 仓库资料索引和运行轨迹字段
4. 重新运行固定失败样本，比较无效工具调用、验证尝试、停止原因和通过率
5. 评估容器内工具执行的成本与收益后，再单独立项

## 测试计划

- 根目录与父级 `AGENTS.md` 按正确顺序加载，越界、缺失、超限和无效编码安全降级
- 项目指令只追加系统上下文，不能覆盖内置提示词
- 无写入任务不注入验证提醒；写入后无命令仅提醒一次；写入后有命令不提醒；取消与工具上限不额外提醒
- SWE-bench 环境契约仅列出存在的候选资料，不读取完整内容
- 结果轨迹保留验证提醒、写入和验证命令统计

## 验收标准

- 在真实项目中启动 Epsilon 时，模型可见受限且有来源标识的项目指令
- 修改后不会在没有任何验证尝试时直接以“完成”结束超过一次
- 验证策略不影响只读和纯对话任务，不引入无限循环
- 无 `AGENTS.md` 的 SWE-bench 仓库仍能获得可读取的测试资料索引
- 评测报告能区分 Agent 宿主环境验证失败、任务补丁失败和官方 Harness 环境失败
