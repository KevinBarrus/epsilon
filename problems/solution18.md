# 第十八轮优化方案：稳定历史与可变尾部的两段式流渲染

## 目标与边界

- 消除长模型回复流式输出中途停顿、结束后补齐的问题
- 保持行内终端历史、最终 Markdown 高亮、输入框、状态栏、取消、工具和 Session 持久化的现有行为
- 本轮只改 TUI 的助手文本展示链路，不修改模型客户端、Agent Loop、工具循环和 Markdown 语法
- 不增加新依赖，不引入通用事件总线或第二套 Markdown 解析器

## 统一设计

将正在生成的助手消息拆成两个展示区域：稳定历史与活动尾部。

```text
模型正文分片
  ↓
流式条目控制器
  ├── 完整且稳定的行 → InlineHistory → 终端主屏幕历史
  └── 未结束或结构未闭合的尾部 → prompt-toolkit 活动视图
                                      ↓
                                  下一分片只重绘尾部
```

原始完整正文仍由流式条目控制器保存，供最终 Markdown 渲染、Session 持久化和取消恢复使用。稳定历史只是不再参与活动视图的重复布局，不是丢弃原文。

## 问题一方案：引入最小流式条目控制器

### 实施步骤

1. 在 `screen.py` 内新增仅服务助手活动条目的私有控制状态，不新增跨模块抽象
2. 控制状态保存：完整原始正文、已提交到历史的源文本长度、当前活动尾部，以及代码块和表格是否需要暂缓提交
3. `append_to_entry()` 收到助手正文时，不再直接将“完整正文”交给 `FormattedTextControl`
4. 控制器先追加原始正文，再识别可安全提交的完整行；安全行写入 `InlineHistory`，活动控件仅保留其后的尾部
5. 每次更新后，活动控件只渲染可变尾部，避免已稳定正文重复参与 Markdown 解析和 prompt-toolkit 布局

### 稳定行规则

- 普通 Markdown：以换行结束的行可提交
- 未结束普通行：保留在活动尾部，等待后续分片补全
- 代码块：从开启围栏到闭合围栏期间保留为活动尾部，使用现有流式基础代码样式；闭合后再整体提交
- 表格：从识别为表格的表头开始保留为活动尾部，直到表格结束，避免后续行改变已有列宽
- 思考过程与正文继续使用现有分隔标记；本方案只处理正文稳定行，不改变思考展示策略

## 问题二方案：复用 `InlineHistory` 持续提交稳定内容

### 实施步骤

1. 为流式助手条目增加“发布稳定片段”的内部路径，复用现有 `InlineHistory.add()` 和异步 `flush()`
2. 稳定片段使用现有 Markdown 渲染入口生成带样式的格式化文本，再写入终端主屏幕历史
3. 已写入历史的内容从活动条目中移除，因此活动视图不会随着整条回复增长
4. 回复结束时，先发布剩余尾部，再沿用现有最终高亮和提交逻辑
5. 取消或模型异常时，同样发布已生成尾部，并保持现有 `(cancelled)`、错误提示和 Session 写入语义

## 问题三方案：限制活动控件的工作范围

### 实施步骤

1. 不修改 prompt-toolkit 渲染器，也不再用 `sleep(0)` 或额外后台队列掩盖问题
2. 活动控件只保留未结束行或未闭合 Markdown 结构，其内容规模不随普通长回复无限增长
3. 保持应用已有 `min_redraw_interval=1/60`，让渲染器继续合并同一帧内的尾部更新
4. 回复结束后再对完整原文执行一次完整 Markdown 高亮，用于最终条目和之后的终端历史重排

## 分层边界

- `ui.py`：继续只把 `TextDelta` 交给界面，不知道行提交、代码围栏或终端历史
- `screen.py`：维护活动条目生命周期、稳定/尾部划分与最终提交
- `inline_history.py`：继续只负责带样式片段的终端输出，不判断 Markdown 结构
- `markdown.py`：继续只负责文本到格式化片段的转换，不维护流状态
- `agent_loop.py`、`openai_client.py`：不改动，模型事件仍按原顺序传递

## 测试计划

- 普通文本：连续小分片中，已换行内容进入历史，活动条目只保留最后未结束行
- 长回复：模拟数千个正文分片，确认活动控件内容有上界，最终原文完整且顺序正确
- 代码块：未闭合时不提前提交，闭合后完整写入，最终高亮保持现有行为
- 表格：表格行流式到达时不提前固定列宽，表格结束后格式正确
- 取消与异常：部分正文既写入会话也能在终端历史中看到，不重复发布
- 回归：思考展示开关、working 条目、工具调用、输入框、状态栏、回复最终提交和恢复会话均保持原行为

## 验收标准

- 长普通正文不再出现“中途停住，结束后补齐”
- 活动 `FormattedTextControl` 不再持有整条持续增长的普通回复
- 代码块和表格不闪烁、不损坏、不丢失最终 Markdown 样式
- 取消、异常和正常结束时，完整内容顺序一致且不重复写入终端历史
- 相关单元测试通过，并完成一次真实长回复手动验证
