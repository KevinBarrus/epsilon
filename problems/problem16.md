# 问题 16：全屏对话视口与终端原生能力冲突

## 问题一：应用接管鼠标后终端缩放失效

当前界面使用 `full_screen=True` 和鼠标上报协议，由应用管理对话滚动与文字选区。普通滚轮可以进入应用，但 Ctrl+滚轮也会离开宿主终端，导致终端原生缩放失效。

删除拖选复制逻辑不能解决该问题，因为冲突发生在鼠标上报层，而不是复制回调中。

期望行为：

- 普通滚轮和触摸板查看终端中的历史对话
- Ctrl+滚轮继续由宿主终端缩放字体
- ↑/↓ 只处理输入框光标和输入历史，不承担对话滚动
- 不在应用内模拟终端字体缩放

## 问题二：退出后对话内容从终端消失

全屏界面运行在终端备用屏幕中。Ctrl+D 或 `/quit` 退出后，终端恢复启动前的主屏幕，对话内容随之不可见，只能重新恢复 Session 查看。

期望行为：

- 已完成的对话写入终端主屏幕回滚区
- Ctrl+D 退出后仍可直接滚动查看本次对话
- 退出后展示本次运行的 Token 用量
- 退出后展示 `epsilon resume <session-id>` 恢复指引

## 问题三：稳定历史与临时界面混在同一个容器

当前 Logo、历史消息、流式回复、工具活动、输入框和状态栏共同参与全屏布局。切换为行内视口后，如果继续整体重绘，可能重复输出历史、污染终端回滚区，或者让 spinner 的每一帧都永久留在终端中。

需要明确区分：

- 已完成、只写一次的对话历史
- 尚未完成、允许重绘的流式内容和工具状态
- 始终位于底部的输入框、审批界面和状态栏

## 问题四：`/auto-copy` 与终端原生选区职责重叠

行内视口不再接管对话区鼠标。对话区选区和松开复制应由宿主终端负责，应用无法可靠修改宿主终端的自动复制设置。

`/auto-copy` 因此失去明确职责，应当废除。输入框内的 Ctrl+C 复制仍由应用处理。
