# 指标效度修正：哪些结论保留，哪些降级

> 起因见 `design/evaluation.md` 第十四节。
> **一句话**：我们用"任意事实清单的命中率"当"读得多深"的主指标，而这把尺子不成立
> （清单选题标准是"答案只存在于源码"，**不含"好报告本该提到"**；源码里具名常达成千上万，命中主要反映运气与篇幅）。

## 一、总原则

| 类别 | 处置 |
|---|---|
| **硬指标**（token / 墙钟 / 工具错误 / 重试次数 / 客观通过项） | ✅ **保留，不受影响** |
| **客观判据**（引用的路径或标识符**是否存在**、是否编造） | ✅ **保留，不受影响** |
| **事实清单覆盖率** | ⚠️ **降级为"下界"，不得单独支撑结论** |

**关键区分**：凡是"**要猜考哪几个**"的指标都受影响；凡是"**真就是真、假就是假**"的指标都**不受影响**。

## 二、逐条处置

| # | 结论 / 数字 | 出处 | 处置 | 理由 |
|---|---|---|---|---|
| 1 | 多 Agent 更贵：共享 1.76× / worktree 3.60× | `problems/multi-agent-arms.md`、`problems/big-repo-read-compare.md` | ✅ **保留** | token 是硬指标 |
| 2 | fork 不划算：C = 3.19× B、覆盖率零回报 | `problems/oncall-read-compare.md` | ✅ **保留** | 主依据是 token 与实际无交付物；"覆盖率零回报"只是旁证 |
| 3 | 完成门能**拦编造、逼真读**：标识符真实率 27/109 → 282/285、路径 53/53 | `problems/completion-gate-v3.md` | ✅ **保留** | **存在性核验是客观判据** |
| 4 | Agent 会自称完成（门之前约 10% 覆盖率即报 `complete`） | `problems/completion-gate.md` | ✅ **保留** | 行为观察 + `stop_reason` 是硬事实 |
| 5 | 验证 ≠ 探索（minimax-code：≤14KB 证据简报） | `ref/agent-completion-gate.md` | ✅ **保留** | 设计原则，与测量无关 |
| 6 | **"扇出读把覆盖率从 10% 提到 27.5%"** | `problems/big-repo-read-compare.md` | ⚠️ **降级** | 覆盖率即那把不可靠的尺子；且 30/40 是常量题 |
| 7 | **"扇出买广度、不买深度"** | `problems/big-repo-read-compare.md` | ⚠️ **降级** | "广度" = 常量题命中数，本身就是该尺子 |
| 8 | **"三档源码级覆盖率都是 5/6、无差异"** | `problems/oncall-read-compare.md` | ⚠️ **降级** | 同因；但"**语料小到单 Agent 能全读时不可能有差异**"这条**结构论证仍然成立** |
| 9 | **"门后覆盖率只 +1/9，判定负面"** | `problems/completion-gate-v3.md` | ⚠️ **降级**（且该轮另有 bug 污染） | 覆盖率不可靠 + 该轮跑中修过两个 bug |

**降级的含义**：**数字保留在文档里**（不删证据），但必须加注：
> ⚠️ **该指标（事实清单覆盖率）效度不足，不得单独支撑结论**；
> 结论若仅依赖该指标，应视为"**未证实**"。

## 三、降级后仍然成立的两条（**结构论证，不依赖该尺子**）

1. **语料小到单 Agent 能全读时，扇出读不可能有覆盖率优势**——这是**逻辑推论**（搜索空间没变），不是测量结果；
2. **门能拦编造**——依赖**存在性核验**（客观），与"考哪几个"无关。

## 四、需加注的文档清单

- `problems/big-repo-read-compare.md`（结论 6、7）
- `problems/oncall-read-compare.md`（结论 8）
- `problems/completion-gate.md` / `problems/completion-gate-v3.md`（结论 9）

**加注格式统一为**（放在相关小节下方）：

```
> ⚠️ 指标效度提示：本节引用的"源码级覆盖率"基于**任意挑出的源码事实清单**，
> 命中主要反映运气与报告篇幅，**不得单独支撑结论**（见 design/evaluation.md 第十四节）。
> 本节中仅依赖该指标的判断视为**未证实**。
```

## 五、不受影响的部分（可继续引用）

- 所有 **token / 墙钟 / 工具错误 / 重试** 数字；
- **交付物完整性**（结构化要求的 pass/fail）；
- **无编造**（存在性核验）类结果；
- **客观通过项**（`tsc`、测试、命令退出码）。
