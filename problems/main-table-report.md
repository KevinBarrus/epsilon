## 四、go/no-go 判定

- actual_tokens 降幅 ≥ 15%：**不达标**。B 相对 C 在产出补丁的 11 题上降幅 2.5%（全 12 题 2.7%），远低于 15%
- 通过数不低于 A：**达标**。B 7/12 = A 7/12
- token 对比只在产出补丁的任务上做：已执行

## 五、结论

- 防火墙在 12 题规模上的真实 token 收益约 2–3%，落在单次运行方差内，不是主杠杆
- 单题冒烟看到的「约一半」主要来自轮次数与运行方差，不是防火墙本身
- 与 problem28 统计一致：基线 881 条工具结果仅 2% 超过 8k 字符，防火墙覆盖的输入占比很小
- B 通过数不低于 A；C 少 1 题为运行噪声（13590 在 C 档 14 轮 / 6.4 万 token 提前结束）
- 后续杠杆应回到驱逐/压缩（需更低预算才触发），或下调防火墙阈值以覆盖更多输出
