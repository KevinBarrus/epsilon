# 问题 19：真实基准评测的隔离、工具契约与回合收尾

## 问题一：评测工作区暴露了基准答案

当前真实 SWE-bench 任务直接在包含 `.git` 的仓库副本中运行。Agent 可以通过命令工具读取提交历史、分支或差异，从而获得目标修复信息。该结果不能代表 Agent 对任务的真实理解和修复能力。

此外，Session 文件和评测日志会写入任务工作区，既污染待测仓库，也会让“补丁是否只修改目标文件”的检查失真。

## 问题二：文件读取工具的契约与模型常用工作流不匹配

`read_file` 只声明并实现了完整文件读取，但模型会自然尝试传入 `offset`、`limit` 分段阅读大文件。当前校验层静默忽略未知字段，工具实际上重复返回文件开头，模型误以为参数生效后会陷入重复探索。

完整读取也会让大文件快速占用工具输出和模型上下文，增加压缩频率与任务耗时。

## 问题三：工具轮次上限以异常结束，已完成工作无法形成闭环

AgentLoop 达到 `max_tool_rounds` 后直接抛出异常。此前已经完成的 assistant 工具调用和 tool result 没有作为显式的本轮增量返回给应用层，界面只能显示通用错误，Session 也无法可靠持久化这些已发生的操作。

这会造成“文件可能已经被修改，但恢复会话后看不到为什么修改”的一致性问题；同时模型没有机会基于最后一批工具结果给用户说明当前进度或未完成原因。
