# 长任务评测报告：驱逐净收益（E0 vs E1）

按 `problems/problem29.md` 执行。同一 Session（T1 修 bug → T2 补测试 → T3 重构），
单任务 `django__django-11001`，模型 `deepseek-v4-pro`，thinking=high，每阶段 80 轮。

## 一、结论

**净收益为负。** 驱逐在长任务里触发了 51 次，但累计 token 比不驱逐高 **64.1%**，
缓存命中率下降 **20.9 个百分点**。省下的"重发旧输出"远不足以抵消前缀缓存失效的损失。

- go/no-go 判据"E1 累计 token ≤ E0 的 85% 且三阶段全过"：**不达标**（E1 是 E0 的 164%）
- 三阶段完成度：两 arm 均 3/3（T1 hard-pass、T2/T3 soft-pass），不是"省 token 但做不完"

## 五、成本构成

`actual_tokens` 含缓存命中部分。按缓存命中约 1/10 计价做成本代理
（未命中 ×1 + 命中 ×0.1）：

| 档位 | 成本代理 |
|---|---|
| E0 | ≈ 177,989 |
| E1 | ≈ 642,190（**约 3.6 倍**） |

驱动成本的是**未命中 token**：驱逐改写历史消息 → 公共前缀失效 → 后续每轮都要按全价
重算，未命中 token 从 7.2 万涨到 50.7 万。

## 六、关键发现

1. **驱逐确实在长任务里触发**（51 次，T1 就 39 次），实验设计成立，不像主表单题 42k 阈值
   够不着；
2. **但净收益为负**：驱逐打断前缀缓存的代价，大于"少重发旧工具输出"的收益；
3. **驱逐替代压缩的假设未被检验**：两 arm 压缩都为 0——E0 的上下文峰值本就没到 84k 压缩线，
   E1 也不需要压缩；
4. **artifact 取回开销为 0**：两 arm 都没有出现 `read_file` + `artifact://` 的取回调用，
   所以负收益不是"取回轮次"造成的，纯粹是缓存失效。

## 七、风险与偏差（如实标注）

1. **单样本、无统计力**：每 arm 只跑 1 次、1 个任务，只能定性，不能外推；
2. **轨迹方差是主要混杂**：E1 的 T1 跑了 63 轮、E0 只有 37 轮，agent 行为不同，agent 多做的
   工作也会推高 token。但 cache_hit_rate 的 20.9 pt 下降是驱逐的直接指纹，不是轮次差异能解释的；
3. **软验证不够硬**：T2/T3 的 `soft-pass` 只证明"没破坏 + 测试通过"，不能证明质量，已与
   SWE-bench 通过率严格分开；
4. **E1 重跑过一次**：首次 E1 因 `402 Insufficient Balance` 在 T3 中断，无有效结果，已归档为
   `long-task-E1-partial-balance`；本报告用的是充值后完整跑完的 E1。
